# 严格学习模式（第一阶段）

## 页面与入口
- 严格学习模式开关位于「系统设置 → 严格学习模式」。
- 开启后，桌面右下角显示学习中心悬浮入口；关闭后隐藏。
- 学习中心使用全屏页面，沿用参考图的浅奶蓝背景、白色圆角任务卡片和紧凑状态反馈。
- 页面顺序：用户资料区（含连续打卡火花与轮船小图标）→ 今日进度 → 留言板 → 睡眠报告 → 专注学习 → 晚间主动回忆 → Char 审核状态。
- 用户资料包含昵称、两行可编辑文字、头像和横幅。监督 Char 从现有角色列表选择。
- 头像和横幅上传时会自动缩放/压缩到单张不超过约 320 KB，以免学习记录快照超过云同步请求体限制。

## 任务数据
- 睡眠规则的单项设置更新采用嵌套合并，修改入睡/起床时间时不会意外清空已设置的最低睡眠时长。
- 睡眠凭证：视觉服务提取报告对应的起床日期、入睡时间、醒来时间和总时长。用户可在严格学习设置中配置入睡截止时间、起床允许范围，并可选设置最低睡眠时长；日期必须与提交当天一致，且已配置的条件全部符合才审核通过。起床范围支持跨午夜。未配置必需时间规则时只识别、不通过。
- 专注凭证：视觉服务提取手环的今日累计专注时长、手机锁屏日期和时间，并检查两类设备信息是否同框。只接受日期为当天的凭证。
- 专注时长采用覆盖写入：新数值高于或等于已审核数值时更新为新数值；新数值更低时要求用户明确确认后覆盖，不进行累加。
- 已审核的睡眠/专注记录不会被一次识别失败、日期不符或未达标的新提交覆盖；较低的专注时长作为待确认候选值单独保存，确认前保留原有审核结果。
- 每日目标目前显示为 8 小时。
- 晚间主动回忆要求填写「今天学了什么？」，补充说明为可选。保存后，回忆内容和 Char 的简短回应会写入监督角色的原有聊天会话。
- 连续打卡要求睡眠报告审核通过、专注学习审核通过且累计达到 8 小时、晚间主动回忆已提交，三项全部完成才计入当天。
- 连续打卡天数按自然日计算；漏掉一天后，下次完成三项时从第 1 天重新计算。连续达到 30 天永久解锁轮船，之后断签不收回已解锁奖励。
- 火花天数和轮船进度以资料卡内的小图标展示，不单独增加任务卡片。
- 学习记录按应用账号隔离保存在本机 IndexedDB KV；当前自部署单用户模式固定使用 `local_user`。旧版未分账号的数据通过 IndexedDB 原子事务只迁移给首个成功取得迁移锁的账号。严格模式云同步使用单独共享密钥保护，密钥保存在每台设备本地，不放进学习记录快照。
- 本机和云端学习快照在载入/写入前都会校验日期、任务状态、时长、资料字段和数据结构；发现异常时停止该次加载或同步，不用默认空记录覆盖原数据。本机 JSON 无法解析时，原始 IndexedDB 记录会保留供后续恢复。
- 通用 KV 的旧版 `localStorage` 迁移只有在 IndexedDB 写入成功后才清理旧副本；若写入失败，旧副本保留以便下次重试。

## Char 每日留言
- 监督 Char 使用其现有人设和绑定的文本模型生成一条当日留言。
- 每个日期、每个监督角色只生成一次；生成结果保存在当天记录中，并写入该角色的原有聊天会话。
- 更换监督 Char 不迁移此前的审核记录。

## 全局视觉模型
- 全局视觉 API 在「系统设置 → 视觉模型 API」配置，与聊天文本 API、图像生成 API 独立。
- 当前第一版支持 OpenAI 兼容的视觉接口（HTTPS Base URL、API Key、模型名）。服务端会校验域名解析结果，只允许公开 IP，并在每次请求中固定已校验的 DNS 地址；本机、内网和特殊用途地址会被拒绝。Base URL 不得包含账号密码、查询参数或片段。
- 连接测试会发送一张极小的测试图片，验证模型确实接受图像输入，而不只是文本接口可用。
- 图片只发送给此视觉服务；严格模式不读取聊天模型的 `enableImageRecognition` 开关，也不把原图发送给 DeepSeek。
- 识别置信度为 low 时，学习中心不会自动通过审核；会保留已有审核记录并提示重新上传更清晰的截图。
- 视觉服务返回结构化提取结果；服务端会校验日期、时间、时长、可见性和文本长度，只向学习中心返回白名单字段。识别请求体上限约 12.5 MB，视觉服务响应体上限 1 MB。学习中心只保留提取出的字段和审核状态。
- API Key 由服务端使用 AES-256-GCM 加密后存入 Supabase；浏览器只拿到非敏感配置摘要。

## 部署准备
1. 在 xfloat Supabase SQL Editor 执行 `docs/strict-learning-vision.sql` 和 `docs/strict-learning-sync.sql`。
2. 在 Next.js 服务端环境变量中设置 `VISION_CREDENTIAL_ENCRYPTION_KEY`。可用 `openssl rand -hex 32` 生成 32 字节密钥；不要提交到 Git。 请妥善备份并长期保留；更换密钥前必须先用旧密钥解密并重新加密已有 API Key，否则已保存的视觉 API Key 将无法读取。
3. 生成严格模式云同步共享密钥：`openssl rand -base64 32`。将完整结果设置为托管平台的服务端环境变量 `STRICT_LEARNING_SYNC_SECRET`；不要添加 `NEXT_PUBLIC_` 前缀，不要提交到 Git。修改环境变量后需要重新部署服务端。
4. 确保已配置服务端 Supabase URL 和 Service Role Key。
5. 部署后进入「系统设置 → 严格学习模式」，在「严格模式云同步」中粘贴共享密钥并保存，再点「测试连接」确认服务端密钥与 Supabase 连接正常。其他设备也输入同一密钥一次；密钥只保存在各自设备的浏览器本地存储中。
6. 进入「系统设置 → 视觉模型 API」填写接口、模型和 API Key，保存后测试连接。

## 单用户部署的访问边界
- 当部署启用 `NEXT_PUBLIC_SELF_HOSTED_MODE=true` 时，应用会跳过账号登录，并把服务端请求固定映射到 `local_user`。该模式要求额外配置站点共享访问口令；没有有效配置时会停留在访问页，不会退回到公开访问。
- 在托管平台的**服务端环境变量**中设置 `SELF_HOSTED_ACCESS_PASSWORD` 和 `SELF_HOSTED_ACCESS_SECRET`。建议分别生成：`openssl rand -base64 32`（访问口令）和 `openssl rand -hex 32`（Cookie 签名密钥）。访问口令和签名密钥都至少 32 个字符；两者都不能添加 `NEXT_PUBLIC_` 前缀，也不要提交到 Git。
- 访问口令只在进入站点时验证一次。服务端发放 HttpOnly、SameSite=Lax Cookie，有效期 30 天；浏览器 JavaScript 无法读取口令 Cookie。所有应用页面和 API 都要求有效 Cookie；访问页、口令验证接口和静态资源例外。
- 为兼容不携带网页 Cookie 的外部快捷指令/推送流程，以下入口仍可无站点 Cookie 访问，但各自必须通过独立校验：`/shortcut-run` 使用短时命令 ticket，`/personal-shortcut-run` 只允许跳转到受限格式的 Supabase 函数 URL，`/api/push/bridge-wake` 使用 `bridge_token`，`/api/push/shortcut-commands/deliver-email` 使用 `bridge_token`、动作白名单和个人云源站校验。其他应用 API 仍要求有效站点 Cookie。
- 两个公开 POST 桥接入口均限制请求体：`bridge-wake` 为 4 KB，`deliver-email` 为 16 KB；免 Cookie 不等于免校验或无限制访问。
- 修改访问口令后，旧 Cookie 在有效期内仍然有效；若要立即撤销所有已登录设备，请同时轮换 `SELF_HOSTED_ACCESS_PASSWORD` 和 `SELF_HOSTED_ACCESS_SECRET` 并重新部署。
- 站点口令是网页/API 的入口保护，不会加密浏览器本机 IndexedDB 或 PWA 已缓存的离线内容；共用设备时仍应使用设备锁屏和独立浏览器资料，不要把站点口令当作本机数据加密。
- 访问口令只控制站点访问，不创建账号、不注册、不改变固定的 `local_user` 身份。严格模式云同步仍使用独立的 `STRICT_LEARNING_SYNC_SECRET`；视觉 API Key 仍使用独立的 `VISION_CREDENTIAL_ENCRYPTION_KEY` 加密。

## 当前阶段边界
- 每日留言、凭证审核反馈和晚间回忆内容/回复均写入监督角色的原有聊天会话，并以近期聊天记录作为生成上下文；学习中心直接调用绑定文本模型，尚未接入聊天页完整的工具调用与插件编排流程。
- 凭证图片只发送给全局视觉服务；Char 收到的只有视觉服务提取出的文字字段和规则审核结论。
- 学习记录保存在本机 KV，并可通过受共享密钥保护的服务端接口同步到 xfloat。固定身份为 `local_user`，不需要注册或登录。云端写入采用 revision compare-and-swap；检测到两台设备同时修改时暂停自动覆盖，并提供选择载入云端版本或保留本机版本覆盖云端。该方案不提供自动字段级合并。
- 本分支未执行完整 Next.js build，也未进行真实视觉 API 或 Android 设备测试。GitHub Actions 在仓库层面处于平台禁用状态，不能据此推断构建通过。
